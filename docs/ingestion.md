# جمع‌آوری و پردازش داده

## قرارداد Collector

هر collector باید این مسئولیت‌ها را داشته باشد:

- دریافت داده از یک منبع مشخص
- رعایت rate limit و شرایط استفاده منبع
- پشتیبانی از pagination یا cursor
- تبدیل پاسخ منبع به قالب raw داخلی
- گزارش تعداد رکوردها و خطاها
- امکان اجرای محدود بر اساس زمان یا شناسه

Collector نباید مسئول ذخیره مستقیم مدل نهایی یا تصمیم‌گیری درباره UI باشد.

## Pipeline

1. Scheduler یک `CollectionRun` ایجاد می‌کند.
2. Worker collector را برای منبع اجرا می‌کند.
3. payload خام با شناسه batch ذخیره می‌شود.
4. schema اولیه و فیلدهای ضروری validate می‌شوند.
5. داده به مدل مشترک normalize می‌شود.
6. URL، عنوان شرکت، مکان و فیلدهای مقایسه‌ای استاندارد می‌شوند.
7. duplicate بررسی و رکورد ایجاد یا به‌روزرسانی می‌شود.
8. آگهی‌های دیگر به search index ارسال می‌شوند.
9. نتیجه اجرا و metrics ثبت می‌شود.

## Retry و خطا

- خطاهای موقت شبکه با backoff دوباره امتحان شوند.
- خطاهای اعتبارسنجی بدون retry در صف خطا ثبت شوند.
- برای هر منبع circuit breaker یا محدودیت اجرای متوالی در نظر گرفته شود.
- یک رکورد خراب نباید کل batch را متوقف کند.
- خطای authentication یا تغییر schema باید alert ایجاد کند.

## Idempotency

اجرای مجدد یک batch باید با استفاده از کلید منبع و شناسه خارجی، رکورد موجود را update کند. عملیات ایجاد، به‌روزرسانی و indexing باید قابل اجرای دوباره باشند.

## کیفیت داده

برای هر batch این شاخص‌ها ثبت شوند:

- درصد رکوردهای دارای عنوان
- درصد رکوردهای دارای شرکت
- درصد رکوردهای دارای لینک معتبر
- درصد duplicate
- درصد خطاهای normalization
- میانگین تازگی آگهی‌ها

## الزامات حقوقی و اخلاقی

پیش از فعال‌سازی هر منبع، API رسمی، robots policy، شرایط استفاده و محدودیت ذخیره یا بازنشر محتوای آن بررسی شود. لینک منبع اصلی باید حفظ شود و داده‌های منبع نباید بدون مجوز به‌عنوان محتوای اختصاصی ارائه شوند.
