# مدل داده

## Job

مدل مشترک هر آگهی باید حداقل این مفاهیم را پوشش دهد:

- `id`: شناسه داخلی
- `source`: نام منبع
- `external_id`: شناسه آگهی در منبع
- `canonical_url`: لینک اصلی نرمال‌شده
- `title`: عنوان شغل
- `company_name`: نام شرکت
- `description`: توضیحات
- `location`: مکان یا فهرست مکان‌ها
- `workplace_type`: حضوری، hybrid یا remote
- `employment_type`: تمام‌وقت، پاره‌وقت، قراردادی و غیره
- `seniority`: سطح شغلی
- `categories`: دسته‌بندی‌ها
- `skills`: مهارت‌ها
- `salary`: مقدار، بازه، ارز و دوره پرداخت در صورت وجود
- `published_at`: زمان انتشار منبع
- `expires_at`: زمان انقضا در صورت وجود
- `last_seen_at`: آخرین زمان مشاهده در منبع
- `status`: فعال، منقضی، حذف‌شده یا دارای خطا
- `content_hash`: hash محتوای قابل‌تغییر
- `created_at` و `updated_at`

## RawJobRecord

برای هر داده دریافتی از منبع:

- منبع و شناسه خارجی
- payload خام
- زمان دریافت
- شناسه batch
- وضعیت پردازش
- پیام خطا در صورت شکست

داده خام برای debugging، audit و بازپردازش نگهداری می‌شود و نباید مستقیماً به کاربر نمایش داده شود.

## Source

- نام و کد منبع
- نوع اتصال
- وضعیت فعال بودن
- تنظیمات غیرحساس
- زمان آخرین اجرای موفق
- زمان آخرین اجرای ناموفق
- محدودیت نرخ درخواست

credentialها باید خارج از database اصلی و در secret manager نگهداری شوند.

## CollectionRun

- شناسه اجرا
- منبع
- زمان شروع و پایان
- وضعیت
- تعداد دریافت‌شده
- تعداد معتبر
- تعداد ایجادشده
- تعداد به‌روزرسانی‌شده
- تعداد duplicate
- تعداد خطا
- پیام یا خلاصه خطا

## قوانین یکتایی

1. ترکیب `source + external_id` کلید یکتای اصلی در سطح منبع است.
2. لینک canonical در صورت معتبر بودن به تشخیص duplicate کمک می‌کند.
3. برای duplicate بین منابع، شباهت شرکت، عنوان، مکان و لینک بررسی می‌شود.
4. تشخیص احتمالی باید قابل بازبینی باشد و ادغام قطعی بدون confidence کافی انجام نشود.

## Lifecycle آگهی

```text
DISCOVERED -> NORMALIZED -> ACTIVE -> EXPIRED
                         \-> REJECTED
                         \-> REMOVED
```

اگر آگهی در چند اجرای متوالی دیده نشود، باید طبق سیاست منبع به‌عنوان expired یا unavailable علامت‌گذاری شود.
