# تصمیم‌های معماری

## ADR-001: شروع با Modular Monolith

**وضعیت:** پیشنهادی

**تصمیم:** نسخه اول به‌صورت modular monolith ساخته شود.

**دلیل:** سیستم هنوز حجم و مرز عملیاتی اثبات‌شده‌ای ندارد. این انتخاب سرعت توسعه، تراکنش‌های ساده و هزینه استقرار پایین‌تری دارد و با مرزبندی درست، مهاجرت آینده را محدود نمی‌کند.

## ADR-002: نگهداری داده خام

**وضعیت:** پیشنهادی

**تصمیم:** payload خام هر منبع برای مدت مشخص نگهداری شود.

**دلیل:** تغییر schema منبع، debugging، audit و بازپردازش بدون تماس دوباره با منبع را ممکن می‌کند.

## ADR-003: PostgreSQL در شروع

**وضعیت:** پیشنهادی

**تصمیم:** PostgreSQL هم storage اصلی و هم search اولیه باشد.

**دلیل:** نیازهای اولیه جست‌وجو با full-text search و indexهای مناسب قابل پوشش است. موتور جست‌وجوی جداگانه پس از مشاهده محدودیت واقعی اضافه می‌شود.

## ADR-004: پردازش پس‌زمینه

**وضعیت:** پیشنهادی

**تصمیم:** جمع‌آوری و پردازش در worker و queue انجام شود.

**دلیل:** collectorها طولانی، خطاپذیر و مستقل از درخواست کاربر هستند. اجرای آن‌ها در API باعث timeout و کاهش قابلیت اطمینان می‌شود.
