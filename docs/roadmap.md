# نقشه راه پیاده‌سازی

## فاز صفر: تصمیم‌های پایه

- نهایی کردن منابع اولیه
- انتخاب فناوری‌ها
- نهایی کردن schema آگهی
- تعریف lifecycle و duplicate policy
- تعیین معیارهای کیفیت و SLA

**معیار خروج:** قرارداد داده و مرزهای معماری تأیید شده باشند.

## فاز یک: هسته داده

- راه‌اندازی backend و database
- مدل‌های Job، Source، RawJobRecord و CollectionRun
- migration
- داده seed و تست مدل‌ها

**معیار خروج:** امکان ذخیره و بازیابی یک آگهی نرمال‌شده وجود داشته باشد.

## فاز دو: دو Collector اول

- پیاده‌سازی دو منبع با الگوی مشترک
- pagination، rate limit و retry
- ذخیره raw payload
- ثبت وضعیت اجرای batch

**معیار خروج:** اجرای مجدد باعث رکورد تکراری نشود و خطای یک رکورد batch را متوقف نکند.

## فاز سه: نرمال‌سازی و duplicate

- استانداردسازی عنوان، شرکت و مکان
- validation
- duplicate detection
- expire کردن آگهی‌های قدیمی
- metrics کیفیت داده

**معیار خروج:** داده‌های دو منبع با schema مشترک قابل جست‌وجو باشند.

## فاز چهار: API

- endpoint جست‌وجو
- فیلتر و sorting
- جزئیات آگهی
- health check
- endpointهای مدیریتی با authorization

**معیار خروج:** قرارداد API مستند و تست endpointهای اصلی کامل باشد.

## فاز پنج: داشبورد

- جست‌وجو و فیلتر
- نتایج و pagination
- صفحه جزئیات
- loading، error و empty state
- پنل ساده مدیریت

**معیار خروج:** کاربر بتواند از جست‌وجو تا لینک منبع اصلی مسیر کامل را طی کند.

## فاز شش: آماده‌سازی production

- worker و queue
- scheduler
- monitoring و alerting
- backup و restore test
- rate limiting
- تست بار و امنیت

**معیار خروج:** سیستم قابل استقرار، پایش و بازیابی باشد.

## فاز هفت: رشد محصول

- منابع بیشتر
- ذخیره جست‌وجو
- bookmark
- اعلان فرصت‌های جدید
- relevance بهتر
- موتور جست‌وجوی جداگانه در صورت نیاز
